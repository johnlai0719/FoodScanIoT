## 當前方向

聚焦「掃描到、讀取與解釋」：拍照 → Fog → Cloud Vision → 單一文字外接大框裁切 → Gemini 結構化理解 → Fog／App。本次切換已通過 Reader 單張實際呼叫；切換後完整手機端到端仍待驗證。

展示預備分三種情境：首次雲端分析、重複掃描命中 Fog 快取、Fog 無快取且無法連雲端時暫存任務並於恢復後補送。手機仍須連上 Fog 才能暫存。三種情境尚未全部實機跑通，並不代表已完成離線辨識。

## 統一文字區塊（2026-10-28）

比賽 reader 取消營養標示專屬種子詞、數值擴張及類別，全部以 OCR 段落距離、文字量與密度合併為 `dense_text` 大區塊。原圖與裁圖仍一起交給 Gemini；營養輸出 schema 與計分不變。這項調整不修改研究主線的裁切器。

以已存 c99 Vision 紀錄離線比較，區塊由 3 個變成 2 個，舊營養框的 24 個 OCR 段落全部被同一新框涵蓋。這是單例幾何涵蓋檢查，未呼叫 Gemini，不能解讀為辨識準確度提升或所有版型都完整。稀疏區塊仍可能不被裁出，原圖保留作為上下文。

分區程式修改後，運行中的 Vision reader 需重啟載入；儀表板靜態介面重新整理即可載入新說明，已存範例 API 的新規則則需重啟儀表板後端。既有掃描紀錄保留當時實際框線。

## App 版面與比賽 Demo

App 採用主要開發 worktree `codex/result-overview` 的 `eb51fc7` 畫面：掃描、健康設定、營養圓環與圖例、添加物功能分類及成分詳情。保留比賽版的排隊任務、儀表板回報與 SDK 58。

掃描頁「比賽 Demo 測試」提供兩類操作：

- **介面預覽**：虛構飲料、含乳點心兩案，不打後端、不存查詢歷史、不回報真實掃描完成；結果明確標示示範。
- **實際連線展示**：依序選擇完整雲端（跳過讀快取）、Fog 快取、離線暫存與補送。選擇只調整請求設定，不自動送出、不切斷雲端，也不製造命中或排隊結果；拍照／輸入條碼後仍須按「開始分析」。

虛構案例由 `APP/src/competition/demoCases.ts` 維護；未啟用 Search 或舊版 local-only OCR 開關。

## 目前 Vision 流程重新量測（2026-10-29）

新呼叫 177 案／222 張照片，比較 A：整圖 Gemini，B：目前 Vision＋通用文字區塊＋原圖與裁圖 Gemini。兩組原圖皆縮至長邊2048、每組每案一次；B保留production裁圖提示尾句，屬整套流程比較。

兩組共同成功163案：成分完全相符micro F1為64.41%／65.94%，營養數值完全相符率94.40%／90.57%，配對成功reader平均耗時6.762s／9.392s。F1差異+1.53pp的配對bootstrap95%區間為[-1.72,+4.93]pp，未顯示可確立的提升；平均耗時增加2.630s。這批歷史開發資料與單次API量測不足以支持新版普遍較準或較快，正式服務未因本次結果切換。

A成功169／177、B成功170／177，其餘均JSON解析失敗、未重試。包含失敗的所有嘗試平均耗時8.169s／10.679s。原始結果、圖表、CSV及完整邊界見外層 `共用素材/辨識流程比較/20261029/vision-ab-v2/結果報告.md`。本次共同163案與先前歷史共同163案不是必然相同的案例集合，不能直接跨批次算改善。

評測入口：`tools/benchmark_vision_pipeline.py`（`--audit-only`只盤點，正常執行會產生付費API呼叫）；離線報告：`tools/report_vision_benchmark.py`。推論不接觸GT，不經Fog／快取／資料庫，也不寫儀表板事件。
