# 每份營養與評分基準（2026-10-31）

比賽版 Gemini 仍只擷取影像中可見數值，不要求模型計算。Reader 使用既有 Vision OCR 原文，找出明確的「每一份量／每份量／每份」宣告（公克、g、毫升、mL），且份量必須與 Gemini 的 serving_size 一致。多組不同份量或單位、無單位、片數等不自動換算。

Cloud 在寫入產品資料前，對缺少的每 100 公克／毫升欄位使用 `每份值 × 100 ÷ 每份份量`。既有每 100 數值保持原值，零值保留，缺值不補零。原始每份數值、份量原文及 converted_fields 存在 products.other_nutrition.label，回傳為 data.nutrition_label；現有資料庫不需加欄或重建。App 概覽呈現原始每份資料與換算提示，評分及個人化閾值沿用每 100 基準。

若僅有每份數值卻不能確認份量／單位，錯誤提示會列出已辨識的核心每份數值並說明暫不評分，不再一律描述成漏讀營養數值。

此變更不新增 Google API 呼叫。舊快取結果不會自動重算；驗收請使用重新辨識或 TEST 照片模式。Pi 不需修改轉發格式；手機須載入新版 App。歷史實驗結果不代表這次換算規則的驗證結果。
