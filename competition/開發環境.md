# 開發環境與隔離

更新：2026-10-28。比賽工作檔與Git分支隔離，但資料庫、App識別與服務設定仍須各自配置，不等於完整執行環境已隔離。

## Docker 本機入口（2026-11-03）

本機 PostgreSQL、Vision Reader、Cloud、儀表板已統一放入 `competition` Compose 群組。Docker Desktop 開啟後啟動群組即可，儀表板為 http://127.0.0.1:8787。程式更新使用 `start-competition.bat` 重建；完整設定見 [[本地雲端啟動]]。Pi Fog 與手機 App 仍在各自裝置執行，既有資料庫資料並未因改名建立新副本。

## 手動開發入口

```powershell
python tools/pipeline_dashboard.py
```

預設只綁定127.0.0.1:8787。預設不呼叫付費API，Search實驗區收合。已存照片範例依賴外層本機材料，新clone沒有範例時回傳404。

新Vision reader需要Python套件：FastAPI、uvicorn、Pillow、requests、python-dotenv、google-auth、google-genai、Pydantic2。設定`GOOGLE_APPLICATION_CREDENTIALS`指向本機服務帳戶、`GEMINI_API_KEY`於後端環境，再執行：

```powershell
python tools/reader_vision_competition.py
```

預設127.0.0.1:8181。既有EasyOCR reader入口為`tools/reader_competition.py`（8180）；切換新reader須明確設定Cloud的reader位址，不能同時假稱兩者都在同一請求執行。

接手機需可信任展示網路可達的儀表板位址，App以`EXPO_PUBLIC_PIPELINE_DASHBOARD_URL`選擇性回報；Cloud／reader以`PIPELINE_DASHBOARD_URL`選擇性回報。詳細步驟見[儀表板README](../web/pipeline/README.md)。尚未設登入的觀測器不應公開上網。

## 掃碼後的商品資料提示（2026-11-03）

App 在掃描或輸入完整條碼後，會在條碼欄位下顯示「查詢中／雲端資料庫已有此商品資料／雲端資料庫尚無此商品資料／目前無法確認」。查無資料時引導上傳標示照片；網路或資料庫失敗不會當成不存在，並可重新查詢。

此功能使用 Cloud 的唯讀 `GET /api/products/{barcode}/availability`，僅回傳該條碼是否有商品紀錄，不呼叫辨識 API、不寫入 Fog 快取，也不建立排隊任務。查詢商品庫的入口由 App 的 `CLOUD_URL` 衍生；手機須能連上該 Cloud 位址。Fog 快取仍由原有分析流程判斷，不能將此提示當作 Fog 快取命中狀態。實際分析路由維持使用者設定。

新增後端契約測試 4 項、App hook 測試 6 項通過；主要 App 匯入路徑型別檢查與 iOS export 通過。全專案 typecheck 仍受未使用 Expo 範本檔案的缺少相依與型別錯誤阻擋，未在此次功能修改中處理。尚未以實體手機驗證新提示。
