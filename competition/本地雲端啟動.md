# Competition：Docker 一鍵啟動

本機的 PostgreSQL、Vision Reader、Cloud API、儀表板統一放在 Docker Desktop 的 `competition` 群組。Pi 上的 Fog 與手機 App 仍在各自裝置執行。

## 平常使用

1. 開啟 Docker Desktop，等待引擎就緒。
2. 在 Containers 找到 `competition`，按群組的啟動按鈕。
3. 確認四個容器均為 running／healthy，開啟 http://127.0.0.1:8787。

四個容器為 `Competition-db-1`、`Competition-vision-reader-1`、`Competition-cloud-server-1`、`Competition-dashboard-1`。設定 `restart: unless-stopped`：原本正在執行的容器會隨 Docker 引擎重啟恢復；手動停止的容器須再按啟動。Docker Desktop 本身仍需開啟，可在其設定啟用登入時自動啟動。

更新程式後雙擊 `start-competition.bat`（`start-cloud.bat` 也會轉到相同入口），或在本專案根目錄執行：

```powershell
docker compose up -d --build --wait --wait-timeout 180
```

舊的 `python tools/start_competition_cloud.py` 已改為同一個 Docker 入口，不再另啟本機 Python 服務。

## 連線與資料

- Cloud 對外仍為 3003，容器內為 8000；Pi 和 App 沿用原有 Cloud 位址。本機 `.env` 的 `COMPETITION_CLOUD_BIND` 指定綁定的 Tailscale IPv4；換電腦或 IP 改變時須更新。
- Cloud 透過 `http://vision-reader:8181` 呼叫 Reader，兩者透過 `http://dashboard:8787` 回報儀表板。
- 儀表板 8787 和 Reader 8181 僅發佈至 localhost；既有 Tailscale 儀表板代理繼續使用 localhost:8787。
- `.env` 的 `COMPETITION_POSTGRES_DATA` 指向既有 PostgreSQL 實體資料，改名不建立空資料庫。`COMPETITION_UPLOADS_DATA` 指向共用上傳資料夾，Cloud 與儀表板掛載同一份照片。
- `.artifacts/` 掛載給 Cloud、Reader 和儀表板，保留重設紀錄、Fog 控制 token、展演斷線狀態。
- 儀表板透過 Docker 網路直接連線 PostgreSQL，不需要掛載 Docker socket。
- 容器內的 `DASHBOARD_TRUST_DOCKER_GATEWAY=1` 僅額外信任 Docker 預設閘道所轉送的本機請求；瀏覽器同源檢查仍保留。

## 憑證與重建

`server/.env` 保存本機服務金鑰；`.env` 的 `COMPETITION_VISION_CREDENTIALS` 指向 Google Vision 服務帳戶 JSON。憑證以唯讀 secret 掛載，環境檔、照片與資料庫不打包進映像、不進版控。`competition/requirements.lock.txt` 固定此映像的 Python 套件版本。

換電腦時需準備上述本機檔案及資料；不能只複製映像就假設含完整資料。`competition/Dockerfile` 與根目錄 `.dockerignore` 定義建置範圍。

## 檢查狀態

```powershell
docker compose ps
docker compose logs --tail 50 cloud-server vision-reader dashboard
```

健康檢查不呼叫 Google API。Cloud 等待資料庫、Reader、儀表板就緒後啟動；展演刻意回應 503 時，健康檢查仍檢查 Cloud 服務與資料庫。健康狀態不能取代手機實際辨識驗收。
