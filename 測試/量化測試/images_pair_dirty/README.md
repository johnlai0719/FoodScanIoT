# 配對拍攝的反光臂

建議 6 的實驗資料。**同一件商品拍兩張,只變動反光**,兩張共用一份正解。

設計見 Obsidian `專案管理/實驗設計/02-配對拍攝實驗`。

---

## 兩張照片放哪裡

```
images/<類別>/<case_id>/<檔名>                    ← 乾淨版
images_pair_dirty/images/<類別>/<case_id>/<檔名>  ← 反光版，檔名要一樣
```

**檔名必須完全相同。**評分工具靠 `EVAL_IMAGE_ROOT` 換讀取路徑,
兩邊檔名一致才不用改任何程式:

```bash
# 乾淨臂（預設）
python run_eval.py --out=pred_pair_clean

# 反光臂
EVAL_IMAGE_ROOT=images_pair_dirty/images python run_eval.py --out=pred_pair_dirty
```

## 命名

現有案例到 `c59`,新的從 **`c60`** 開始,格式 `c60_商品名`,與 `cases.json` 一致。

**只有乾淨版進 `cases.json`**(成為 v4.0 新案例)。反光版只放在這裡,
**不登錄為案例、不計入案例數**——否則主測試集的頭條數字會因為刻意拍了
髒照片而被拉低。

## 這次要拍什麼

**20 組，不綁類別。**（2026-08-26 修訂，原本訂的是四類各 5 件）

判準只有一條，而且在買的當下就要能回答：

> 這件商品能不能拍出一組「低反光」和一組「明顯反光」？
> 能就收，不能就換。**與分數無關。**

**為什麼不綁類別**：反光是材質造成的，類別只是代理變數。同一類裡材質差很多——
飲料有 PET 瓶、鋁箔包、紙盒；泡麵有收縮膜杯也有袋裝。照類別硬配可能買到
五件全是紙盒，那幾組壓不出反光、等於白拍。

**兩條必須守住的規則**：

1. **納入與否在買的時候決定，不能拍完看分數再挑。**
   拍 30 組留下差距最大的 20 組＝事後挑樣本，實驗就毀了。
2. **逐件記材質**（PET 瓶／鋁箔包／紙盒／鋁箔軟袋／收縮膜／塑膠盒＋熱感應貼紙…）
   與類別。材質只作事後描述，不拿來分組報數字——20 組切成五格什麼都測不出來。

**仍要避開圓罐與極軟的袋裝**：包裝本身已經很難讀的商品有地板效應，
乾淨版分數就低，反光再壓也壓不出差距。

## 拍攝紀律

1. **一組配對必須同一次、同一位置、連續拍完。** 這是唯一不能拆的單位。
   不可拿舊照片當乾淨版——那會把拍攝條件跟器材、時期混在一起。
2. **不要一個場次只拍一種材質。** 鋁箔袋全在早上窗邊、PET 瓶全在晚上檯燈下的話，
   反光強度就跟材質綁死了。跨場次時每場都混著拍。
3. **記下每個場次的日期與光源。** 拍完檢查配對差值有沒有隨場次分群。
4. **「明顯才算」**：反光斑要落在**標示區域**上，背景反光不算。
5. **乾淨版是相對的，不是零反光**：同一件商品在可控光源下所能取得的最低反光
   狀態即可，標示文字區域仍可能有輕微亮面，只要不遮蔽判讀。收縮膜杯麵在任何
   角度都會有亮面，堅持零反光的話該類商品拍不出乾淨版。

## 正解怎麼寫

**必須獨立於兩張照片**:對著實體包裝轉錄,或另拍一張高解析清楚照來寫。

**不可從乾淨版那張生成正解**——那是循環,乾淨版等於在跟自己比,
量到的差距會被灌高。

好消息:兩張共用同一份正解,**正解的誤差在相減時抵消**,
所以精確度要求比主測試集低,且先寫成分清單即可,不必湊齊 22 欄。
其餘欄位後補時 `set_version` 次版號 +1。

## 拍完之後

```bash
python casetool.py check          # 案例定義與檔案是否對得上
python label_difficulty.py generate   # 補拍攝條件標註（新的 20 案也要標）
python make_backup.py "<備份路徑>/量化測試集_v4.0_<日期>.zip"
```

**備份要重做。**新增案例後舊的 zip 不含這批照片,而正解是唯一不可由程式
重生的資產。舊 zip 不要刪——它是舊版號數字的可重現性依據。
